# ADR-0004: iOS を入力、Web を分析に役割分離する

> **この決定は [ADR-0009](0009-web-first-with-input.md) により置き換えられた。**
> Web にも入力機能を持たせ、開発順序も Web を先行させる。
> 「iOS をジムでの高速入力に特化させる」という趣旨は ADR-0009 に引き継がれている。

- Status: **Superseded by [ADR-0009](0009-web-first-with-input.md)**（2026-09-12）
- Date: 2026-09-12

## Context

iOS と Web の両方を開発する。それぞれにどこまでの機能を持たせるかを決める必要があった。

利用シーンは大きく2つに分かれる。

| シーン | 状況 | 求められること |
|---|---|---|
| セット記録 | ジム。汗をかいた手、片手操作、電波が悪い | 速度・オフライン動作 |
| 週次レビュー | 自宅。落ち着いて判断する | 大きい画面・グラフ・比較 |

## Decision

**iOS = 入力、Web = 分析。この分担を崩さない。**

| | iOS | Web |
|---|---|---|
| トレーニング記録 | ◎ 主 | × |
| 食事記録 | ◎ 主 | × |
| 体組成・周囲長・写真 | ◎ 主 | 閲覧のみ |
| Apple Health 連携 | ◎ 主 | — |
| 週次レポート | 閲覧のみ | ◎ 主 |
| 計画管理・月次目標の引き直し | × | ◎ 主 |

## Alternatives considered

**A. 両方でフル機能を提供する**
却下。実装コストが2倍になり、**両方が中途半端になる**。特に Web に入力機能を作り込むと、iOS の入力最適化への投資が薄まる。

**B. Web（PWA）のみで完結させる**
却下。以下が実現できない。

- HealthKit 連携（体重・体脂肪率・歩数・睡眠・HRV の自動取得）— **これが自作の最大の価値**
- 確実なオフライン動作（ジムの電波環境）
- 触覚フィードバックによるインターバルタイマー

**C. iOS のみ（Web なし）**
却下。週次レビューで複数のグラフを並べて比較する作業は、スマートフォンの画面では成立しない。

## Consequences

**良い影響**

- 各プラットフォームが1つの目的に最適化できる。iOS は入力速度、Web は情報密度
- 実装範囲が明確になり、Phase 1（iOS 記録）と Phase 3（Web 分析）を独立して進められる
- Phase 1 完了時点で、分析はプロトタイプ実装で代替できる（Web を待たずに運用開始できる）

**悪い影響 / 受け入れるコスト**

- 外出先で週次レポートを詳細に見たい場合、体験が劣る（閲覧のみ）
- 計画の修正を iPhone だけで完結できない
- API を両クライアントで共有するため、インターフェース設計に配慮が必要
