# 技術選定

- 記載時点: **2026-09**
- バージョンは定期的に見直す（§9）

## 1. 選定の原則

| 原則 | 内容 |
|---|---|
| **サポート期間内のバージョンを使う** | EOL を迎えたものは使わない。セキュリティ修正が来なくなるため |
| **マネージドを優先する** | DB・認証・ストレージを自前構築しない。個人プロジェクトで運用に払う時間の価値が低い |
| **ロックインを避ける** | データは CSV で出せる形にする。特定サービスが終了しても移行できる |
| **学習も判断軸に含める** | 個人プロジェクトは本番で採用しづらい技術を試せる場（[ADR-0006](adr/0006-go-backend.md), [ADR-0012](adr/0012-terraform.md)） |

|---|---|---|---|

## 3. バックエンド（Go）

| 項目 | 選定 | 理由 |
|---|---|---|
| 言語 | **Go 1.27** | [ADR-0006](adr/0006-go-backend.md)。API の独立、バッチ処理、型安全性、学習 |
| ルーティング | **標準 `net/http`** または **chi** | Go 1.22 で `ServeMux` がパスパラメータに対応したため標準で足りる。Gin は機能過多 |
| DB ドライバ | **pgx/v5** | PostgreSQL 専用。`database/sql` より高速で、型対応が厚い |
| クエリ | **sqlc** | SQL から型付き Go コードを生成。ORM の抽象を挟まず、生成物が読める |
| マイグレーション | **golang-migrate** | SQL ファイルでバージョン管理。定番 |
| API スキーマ | **OpenAPI + oapi-codegen** | [ADR-0007](adr/0007-openapi-schema-driven.md)。3言語の型を1定義から生成 |
| ログ | **`log/slog`**（標準） | 構造化ログが標準ライブラリに入った。外部依存を増やさない |
| エラー監視 | **sentry-go** | [private/learning/sentry.md] |
| Lint | **golangci-lint** | 複数の linter を束ねる。Go の事実上の標準 |
| MCP | Go の MCP ライブラリ | API と同じバイナリに載せる（[ADR-0011](adr/0011-go-analytics.md)） |

### Go のバージョン運用に注意

**Go には LTS がない。** 年2回（2月・8月）にメジャーリリースがあり、**サポートされるのは最新2世代のみ**。

```
2026-02  Go 1.26 リリース
2026-08  Go 1.27 リリース  ← 1.25 がサポート外に
```

つまり **1年放置するとセキュリティ修正が来なくなる**。Node.js の LTS のような「長期間そのまま」が成立しない点が最大の違い。**年2回の更新を運用に組み込む必要がある**（§9）。

## 4. フロントエンド（Web）

| 項目 | 選定 | 理由 |
|---|---|---|
| フレームワーク | **Next.js 16**（App Router） | Server Components で分析結果の描画をサーバ側に寄せられる。Vercel への最短経路 |
| ランタイム | **Node.js 24 LTS** | Active LTS。18 は EOL |
| パッケージマネージャ | **pnpm** | **phantom dependency を構造的に防ぐ**（npm/yarn は hoisting により未宣言の依存も import できてしまう）。ディスク効率と workspace サポートも利点 |
| 言語 | **TypeScript 5.x** | OpenAPI から型を生成するため必須 |
| 型生成 | **openapi-typescript** | `openapi.yaml` から型を生成 |
| スタイル | 未決 | Tailwind か CSS Modules。Phase 1a で決める |
| テスト | **vitest** | Jest より高速。Vite ベース |
| エラー監視 | **@sentry/nextjs** | Source Map の自動アップロードに対応 |

**Web に重い UI ライブラリを入れない。** 分析UIは作らない方針（[ADR-0010](adr/0010-mcp-over-analysis-ui.md)）のため、必要なのは入力フォームと最小限のサマリ表示のみ。

## 5. iOS

| 項目 | 選定 | 理由 |
|---|---|---|
| 言語 | **Swift 6.3** | Xcode 26.4 以降に同梱 |
| UI | **SwiftUI** | 宣言的UI。UIKit を書く理由がない |
| ローカルDB | **SwiftData** | オフライン優先の設計に必要。Core Data の後継 |
| **Deployment Target** | **iOS 17.0 以上** | **SwiftData が iOS 17+ を要求するため** |
| ビルド SDK | **iOS 26 SDK 以上** | 2026-04-28 以降、App Store Connect へのアップロードに必須 |
| HealthKit | 標準 | 体重・歩数・睡眠・HRV・安静時心拍の取得 |
| 型生成 | **swift-openapi-generator** | `openapi.yaml` から Swift クライアントを生成 |
| 配信 | **TestFlight** | Apple Developer Program 年 $99 が必要 |

### ビルドSDK と Deployment Target は別物

混同しやすいので明記する。

| | 意味 | 本プロジェクト |
|---|---|---|
| **ビルド SDK** | どの SDK でコンパイルするか | **iOS 26 以上**（Apple の要求） |
| **Deployment Target** | どの OS バージョンから動くか | **iOS 17 以上**（SwiftData の要件） |

**iOS 26 SDK でビルドしても、iOS 17 の端末で動かせる。** App Store の要求は前者にのみかかる。

## 8. 言語ごとのテスト方針

| | フレームワーク | 方針 |
|---|---|---|
| Go | **標準 `testing`** | **テーブル駆動テスト**。`t.Parallel()` を付ける。testify は使わない（標準で足りる） |
| TypeScript | **vitest** | UI のテストは必須としない |
| Swift | **XCTest** / Swift Testing | 同上 |
| Python（reference） | **pytest** | 検証基準として維持（[ADR-0011](adr/0011-go-analytics.md)） |

## 9. バージョン更新の方針

| 対象 | 更新頻度 | 理由 |
|---|---|---|
| **Go** | **年2回（2月・8月）** | **LTS がなく最新2世代のみサポート**。放置するとセキュリティ修正が来ない |
| **Node.js** | **年1回（10月）** | 次の Active LTS が出たタイミング。偶数バージョンのみ使う |
| **PostgreSQL** | Supabase の提供に従う | メジャーアップグレードは Supabase 側の手順で行う。**上げたら `compose.yaml` も同時に上げる**（ローカルだけ先行させない） |
| **Xcode / Swift** | **Apple の SDK 要求に従う** | App Store Connect の最低SDKが上がったら追従する（年1回程度） |
| 依存ライブラリ | **週次（Dependabot）** | パッチは自動マージ可。メジャーは手動確認 |
| Terraform プロバイダ | 四半期 | 破壊的変更が入ることがあるため、まとめて対応する |

**Go の更新が最も忘れやすい。** Node.js の LTS に慣れていると「1年は放置できる」と誤解するが、Go は半年で1世代古くなる。Dependabot の `gomod` 設定で Go 本体のバージョンも追跡する。

## 10. 却下した選択肢

| 検討したもの | 却下理由 |
|---|---|
| Next.js Route Handlers を API にする | API が Web に従属する（[ADR-0006](adr/0006-go-backend.md)） |
| Python (FastAPI) | 3言語になる点は Go と同じで、イメージサイズとコールドスタートで劣る |
| Connect (Protobuf) | 技術的には優れるが、Go とインフラで既に新要素が2つある（[ADR-0007](adr/0007-openapi-schema-driven.md)） |
| gRPC | ブラウザから直接呼べず、通信頻度が低いため性能優位が効かない |
| ORM（GORM 等） | sqlc の方が生成物が読め、SQL の制御が効く |
| testify | 標準 `testing` + テーブル駆動で足りる。依存を増やさない |
| Gin / Echo | Go 1.22 の `ServeMux` 改善で標準が実用的になった |
| Neon（DB） | シンガポールリージョンでレイテンシが乗る |
| Datadog | 無料枠が「5ホスト・1日保持」で個人には実用性が低い |
| husky（Git hooks） | Node.js 必須。本プロジェクトは Go/Python/TS が混在するため lefthook |
| npm / yarn | **hoisting により宣言していない依存も import できる**（phantom dependency）。pnpm は構造的に防ぐ |
