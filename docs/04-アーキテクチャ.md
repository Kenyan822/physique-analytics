## 役割分担の原則

**役割は「汎用 / ジム特化」で分ける**（[ADR-0009](adr/0009-web-first-with-input.md)、[ADR-0004](adr/0004-ios-input-web-analysis.md) を置き換え）。

| | Web | iOS |
|---|---|---|
| 位置づけ | 汎用クライアント（入力も分析も） | ジムでの高速入力に特化 |
| 独自の価値 | 大画面での分析・計画管理・長文入力 | **入力速度・オフライン・HealthKit 連携** |

**開発は Web 先行。** 1人開発では反復の速さが完了時期を左右するため、基盤（スキーマ・API・認証・デプロイ）を最も検証しやすい環境で固める。iOS はその検証済み API に乗る。

## データフローと「正」の所在

| データ | 一次入力 | 正 |
|---|---|---|
| セット記録・食事記録 | iOS（オフライン） | ローカルDB → 同期後は Postgres |
| 体重・体脂肪率・歩数・睡眠 | **Apple Health（自動）** | Postgres |
| HRV・安静時心拍・深睡眠 | **Apple Watch（自動）** | Postgres |
| 周囲長・写真 | iOS（手入力） | Postgres / R2 |
| **分析ロジック** | — | **`api/internal/analytics`（Go）** |

**分析ロジックの正は Go（`api/internal/analytics`）に置く**（[ADR-0011](adr/0011-go-analytics.md)）。API と MCP サーバーが同じパッケージを共有するため、分析ロジックが1箇所に集約され、DB アクセス層も1つで済む。

**Phase 0 の Python 実装は `reference/analysis/` に残す。** 目的は移植の検証で、**Go 実装の出力が同一データに対して一致することを受け入れ条件とする**。移植時のバグを検出する客観的な手段が他にないため。

## スキーマ駆動開発

**型の定義は `openapi.yaml` だけに置き、3言語すべてコード生成する**（[ADR-0007](adr/0007-openapi-schema-driven.md)）。

```
openapi.yaml                        ← 唯一の正
    ├─ oapi-codegen             → api/  (Go: サーバインターフェース + 型)
    ├─ openapi-typescript       → web/  (TypeScript: 型)
    └─ swift-openapi-generator  → ios/  (Swift: クライアント)
```

Go・TypeScript・Swift で同じ構造を手書きすると必ず乖離し、**乖離は実行時エラーとしてしか現れない**（コンパイルは通ってしまう）。生成にすればこれが構造的に起きない。

**生成物はコミットし、CI で最新性を検証する。** 生成コマンドを実行して差分が出たら失敗させることで、生成忘れを防ぐ。

## オフライン戦略

ジムは電波環境が悪く、記録中の通信は前提にできない。

- **iOS はローカルDB（SwiftData）を正とし、バックグラウンドで同期する**
- **競合は Last Write Wins + 論理削除で解決する**（[ADR-0014](adr/0014-sync-conflict-resolution.md)）
- 未同期件数を UI に表示し、同期状態を可視化する

### 競合が起きる経路

[ADR-0009](adr/0009-web-first-with-input.md) で Web にも入力機能を付けたため、**入力経路が2つになった**。

```
1. ジムで iOS に記録（オフライン）
2. 帰宅後、Web で同じ日を修正
3. iOS が復帰して同期 ← 競合
```

**削除を物理削除にすると、オフライン側の古いレコードが復活する**（存在しないレコードは LWW の比較対象にならないため）。`deleted_at` を立てる論理削除にすることで、削除も1つの更新として時刻比較できる。

CRDT のような自動マージは**1ユーザーの個人アプリに対して過剰**なため採らない。競合を検知したらユーザーに通知し、自動マージはしない。

## 技術選定

主要な選定は以下。**バージョンを含む詳細は [06-技術選定.md](06-技術選定.md)。**

| レイヤー | 選定 |
|---|---|
| API | **Go 1.27**（[ADR-0006](adr/0006-go-backend.md)） |
| スキーマ | **OpenAPI + oapi-codegen**（[ADR-0007](adr/0007-openapi-schema-driven.md)） |
| Web | **Next.js 16** / Node.js 24 LTS |
| iOS | **Swift 6.3 / SwiftUI / SwiftData**（Deployment Target: iOS 17+） |
| DB | **PostgreSQL 18**（Supabase・Supavisor 経由） |
| 写真 | **Cloudflare R2**（[ADR-0008](adr/0008-r2-photo-storage.md)） |
| IaC | **Terraform**（[ADR-0012](adr/0012-terraform.md)） |

**マネージドサービスを優先し、自前構築しない。** 個人プロジェクトで運用に払う時間の価値が低いため。詳細は [05-インフラ設計.md](05-インフラ設計.md)。

## CI/CD

| | 内容 |
|---|---|
| CI | GitHub Actions（public リポジトリのため無料・無制限） |
| api | golangci-lint + go test + **生成物の最新性検証** + スモークテスト |
| reference | ruff + mypy + pytest（**検証基準として機能させるため CI で回し続ける**） |
| ios | SwiftLint + xcodebuild test（Phase 1 で追加） |
| web | ESLint + tsc + vitest + build（Phase 3 で追加） |
| CD | Web: Vercel（Root Directory を `web/`）／ API: GitHub Actions → Cloud Run |
| 依存更新 | Dependabot（weekly） |

**スモークテストを入れているのは、個別の関数が正しくても全体の組み合わせが壊れるケースを検出するため。** 単体テストだけでは、レポート生成のパイプライン全体が通ることを保証できない。
