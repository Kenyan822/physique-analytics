# 分析設計 — データをどう判断に変えるか

記録は手段であり、目的は**毎週の意思決定**。以下が週次レポートの項目になる。

## 分析1: TDEE の動的推定 【これが基盤】

一般的な TDEE 計算式（Mifflin-St Jeor 等）は個人差 ±20%、活動係数の選択で数百kcal変わるため実用に耐えない。**自分の実測データから逆算する。**

```
TDEE = 平均摂取kcal − (体重トレンドの傾き[kg/日] × 7700)
```

- `7700` は脂肪組織1kgあたりのkcal
- 傾きは直近14〜21日の日次体重に**線形回帰**をかける（単純な差分ではノイズに支配される）
- 減量開始直後の2週間は水分とグリコーゲンの変動が支配的なため除外

例: 平均摂取2200kcal、体重トレンド -0.057kg/日（-0.4kg/週）なら `2200 + 0.057×7700 = 2639 kcal`。

これが実測できれば目標ペースから摂取量が逆算でき（`TDEE + 目標ペース × 7700 / 7`）、毎週再推定することで**代謝適応を自動的に追随できる**。固定の摂取量で押し通す方式が停滞する理由がここにある。

## 分析2: 体組成の分解と体脂肪率の代理指標

家庭用体組成計の体脂肪率は誤差 ±3〜5% で、単日の値は使えない。3つを併用する。

1. **体脂肪率の7日移動平均** — 絶対値は信用せず傾きだけを見る
2. **ウエスト周囲長（へそ）** — 最も信頼できる代理指標。体重が横ばいでウエストが減れば脂肪が落ちて筋肉が付いている
3. **海軍式推定** — 体組成計とは独立した推定なので、2つが同方向に動けば信頼度が上がる

```
BF% = 495 / (1.0324 − 0.19077×log10(waist_cm − neck_cm) + 0.15456×log10(height_cm)) − 450
```

**LBM = 体重 × (1 − 体脂肪率)** の推移を追い、正規化FFMI（`LBM/身長m² + 6.1×(1.8−身長m)`）で筋量の充実度を測る。減量期に LBM 損失が -1.5kg 以内なら成功。

## 分析3: 推定1RM (e1RM) の時系列

筋力は日により±10%動くため、単発の記録では進捗が判定できない。全セットから推定1RMを計算し、回帰直線の傾きで判定する。

```
限界レップ数 r = reps + rir
e1RM = weight × (1 + r / 30)      # Epley
```

**RIR を含めるのが要点。** `80kg×8回 RIR2` は限界10回相当で `106.7kg`、同じ `80kg×8回` でも RIR0 なら `101.3kg` とまったく別の意味を持つ。

r が 12 を超えると Epley の精度が落ちるため、**限界12レップ超のセットは e1RM 計算から除外する**（サイドレイズ・フライ等の高レップ種目は追跡対象外）。

### 判定

種目ごとに直近6週の日別最大 e1RM に線形回帰をかける。

| フェーズ | 期待される傾き | 逸脱時の解釈 |
|---|---|---|
| 増量期 | +0.3 〜 +1.0 kg/週 | ゼロ以下ならボリューム不足か回復不足 |
| 減量期 | -0.1 〜 0 kg/週 | -0.3 以下ならペースが速すぎる（先にボリュームを削る） |

## 分析4: 部位別ボリューム

**有効セット数** = `count(rir <= 4)` を部位別・週別に。**トン数** = `Σ(weight × reps)`。

セット数はレンジ管理（部位別 MEV/MRV は `config.json`）、トン数は「同じセット数でも強度が上がっているか」の確認に使う。肩は前部/中部/後部、背中は広背筋/僧帽筋に分割する（一括では部位内の偏りが埋もれる）。

## 分析5: 停滞検知

「停滞したか」を感覚で判断すると、ほぼ全員が早すぎる判断をする（水分変動を停滞と誤認する）。閾値を先に決めておく。

| 検知項目 | 条件 | 出力 |
|---|---|---|
| 減量停滞 | 体重トレンドの傾き \|slope\| < 0.1kg/週 が14日継続 かつ 摂取kcalのCV < 10% | 摂取 -150kcal または 歩数 +2000 |
| 筋力低下 | 主要種目の e1RM 傾きが -0.3kg/週 以下 | ボリュームを削る / 減量ペースを緩める |
| 回復不足（主観） | fatigue 7日平均 > 3.5 または sleep_h 7日平均 < 6.5 | 回復週を前倒し |
| **回復不足（客観・Watch）** | **HRV 7日平均が30日基準から -15%** | 回復週を前倒し / 減量ペースを1段落とす |
| 同上 | **安静時心拍 7日平均が基準 +5bpm** | HRV と合わせて判断。両方悪化なら回復優先 |
| 同上 | 深睡眠 7日平均 < 60分 | 睡眠を減量ペースより優先する |
| 摂取の下限 | 推奨摂取が 体重×24kcal を下回る | 摂取を削らず歩数で赤字を作る |
| 炭水化物の枯渇 | 目標炭水化物が 200g を下回る | 同上 |
| 記録漏れの疑い | 摂取kcalの欠損が週2日以上 | 3日間の厳密計量 |

**「減量停滞」の真の原因が代謝適応であるケースは少数で、大半は (a) 記録漏れ (b) NEAT（歩数）の無自覚な低下。** だから歩数を毎日記録する。摂取を削る前に必ず歩数を確認する。

**HRV と安静時心拍は Apple Watch 装着時のみ。** 主観の疲労度より早くオーバートレーニングを検知でき、特に減量期と大会前に効く。30日移動平均を基準（baseline）とし、直近7日との乖離で判定する。絶対値には大きな個人差があるため、他人の数値と比べる意味はない。

## 分析6: 相関分析（データが3ヶ月溜まってから）

一般論ではなく個人の反応を知ることが、計画後半の差を作る。

- 睡眠時間・深睡眠 → 翌日の e1RM 達成率（何時間を割ると筋力に出るか）
- HRV → 翌日のトン数（自分にとって HRV がどこまで落ちるとパフォーマンスに出るか）
- 歩数 → 体重変化の残差（自分の NEAT の寄与度）
- 炭水化物量 → その日のトン数
- 部位別セット数 → その部位の周囲長の変化（自分の最適点）

サンプル数が少ない段階の相関は偶然を拾う。**最低90日、できれば各フェーズ完了後に実施。**

## 週次レポートの構成

```
1. 体重トレンド（7日平均・傾き・LBM・FFMI）
1.5 次の大会まで（残り週数・必要ペース）
2. 当月目標との進捗
3. 推定TDEE と 来週の推奨摂取
4. PFC 目標と達成率
5. 部位別 有効セット数（MEV/MRV 判定）
6. 主要種目の e1RM と傾き
7. リカバリ / 周囲長
8. 今週のアクション
```

**「8. 今週のアクション」が最終成果物。** 数字の羅列ではなく、来週何を変えるかが1行で出ることをゴールとする。
