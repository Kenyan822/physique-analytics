## 1. Supabase（DB + 認証）

### 手順

1. [https://supabase.com](https://supabase.com) → GitHub でサインアップ
2. **New project**
  - Name: `physique-analytics`
  - **Database Password**: 生成して**必ず保存**（後から見られない）
  - **Region: `Northeast Asia (Tokyo)`** ← 重要。他を選ぶとレイテンシが乗る
  - Plan: Free

### 取得する値

**Project Settings → Database → Connection string** から2種類を取る。


| 用途           | ポート      | モード                    | 使う場所                   |
| ------------ | -------- | ---------------------- | ---------------------- |
| **アプリから**    | **6543** | Transaction（Supavisor） | `DATABASE_URL`         |
| **マイグレーション** | **5432** | Direct                 | `MIGRATE_DATABASE_URL` |


```
# アプリ用（Supavisor 経由。必ずこちらを使う）
postgres://postgres.xxxx:[PASSWORD]@aws-0-ap-northeast-1.pooler.supabase.com:6543/postgres

# マイグレーション用（直接接続）
postgres://postgres.xxxx:[PASSWORD]@aws-0-ap-northeast-1.pooler.supabase.com:5432/postgres
```

**Project Settings → API** から認証用の値を取る。


| 値                     | 公開してよいか        | 使う場所              |
| --------------------- | -------------- | ----------------- |
| Project URL           | ✓              | Web / iOS         |
| `anon` key            | ✓              | Web / iOS         |
| `service_role` key    | **✗ 絶対に公開しない** | 使わない（クライアントに渡さない） |
| JWT Secret / JWKS URL | ✗              | Go API（JWT検証）     |


JWKS URL は `https://<project>.supabase.co/auth/v1/.well-known/jwks.json`。

### 注意

- **7日間アクセスがないとプロジェクトが自動停止する。** keepalive が必要（[05-インフラ設計.md](05-インフラ設計.md) §2.1）
- **Free は2プロジェクトまで**
- **接続は必ず 6543（Supavisor）を使う。** 直接接続は60本で枯渇する（§2.2）
- Transaction mode ではプリペアドステートメントが使えない → pgx に `QueryExecModeSimpleProtocol` を指定する

## 2. GCP（Cloud Run）

### 前提

**課金アカウントの紐付けが必要。** Cloud Run に無料枠はあるが、課金アカウントがないとAPIを有効化できない。**無料枠内なら請求は発生しない**が、予算アラートは設定しておく。

### 手順

```bash
# 1. プロジェクト作成（ID はグローバルで一意）
gcloud projects create physique-analytics-<好きな数字> --name="physique-analytics"
gcloud config set project physique-analytics-<好きな数字>

# 2. 課金アカウントを紐付け（コンソールでも可）
gcloud billing accounts list
gcloud billing projects link $(gcloud config get-value project) \
  --billing-account=<BILLING_ACCOUNT_ID>

# 3. 必要な API を有効化
gcloud services enable \
  run.googleapis.com \
  artifactregistry.googleapis.com \
  secretmanager.googleapis.com \
  cloudscheduler.googleapis.com \
  iamcredentials.googleapis.com

# 4. Artifact Registry のリポジトリを作成
gcloud artifacts repositories create physique \
  --repository-format=docker \
  --location=asia-northeast1 \
  --description="physique-analytics のコンテナイメージ"
```

### 予算アラート（必ず設定する）

コンソール → お支払い → 予算とアラート → 予算を作成

- 金額: **1,000円**（無料枠を超えたら気づけるように）
- しきい値: 50% / 90% / 100%

**個人プロジェクトで一番怖いのは設定ミスによる課金。** 無料枠内の想定でも必ず入れる。

### Workload Identity 連携（GitHub Actions → GCP）

**サービスアカウントキーを発行しない**（[05-インフラ設計.md](05-インフラ設計.md) §6）。GitHub の OIDC トークンで認証する。

```bash
PROJECT_ID=$(gcloud config get-value project)
PROJECT_NUM=$(gcloud projects describe $PROJECT_ID --format='value(projectNumber)')
REPO="Kenyan822/physique-analytics"

# 1. デプロイ用サービスアカウント
gcloud iam service-accounts create github-deployer \
  --display-name="GitHub Actions deployer"

SA="github-deployer@${PROJECT_ID}.iam.gserviceaccount.com"

# 2. 必要な権限（最小限に絞る）
for role in roles/run.admin roles/artifactregistry.writer roles/iam.serviceAccountUser; do
  gcloud projects add-iam-policy-binding $PROJECT_ID \
    --member="serviceAccount:${SA}" --role="$role"
done

# 3. Workload Identity プール
gcloud iam workload-identity-pools create github \
  --location=global --display-name="GitHub Actions"

# 4. プロバイダ（このリポジトリからのみ許可する）
gcloud iam workload-identity-pools providers create-oidc github \
  --location=global \
  --workload-identity-pool=github \
  --display-name="GitHub" \
  --attribute-mapping="google.subject=assertion.sub,attribute.repository=assertion.repository" \
  --attribute-condition="assertion.repository=='${REPO}'" \
  --issuer-uri="https://token.actions.githubusercontent.com"

# 5. サービスアカウントの借用を許可
gcloud iam service-accounts add-iam-policy-binding $SA \
  --role=roles/iam.workloadIdentityUser \
  --member="principalSet://iam.googleapis.com/projects/${PROJECT_NUM}/locations/global/workloadIdentityPools/github/attribute.repository/${REPO}"

# 6. GitHub Secrets に入れる値を出力
echo "WIF_PROVIDER=projects/${PROJECT_NUM}/locations/global/workloadIdentityPools/github/providers/github"
echo "WIF_SERVICE_ACCOUNT=${SA}"
echo "GCP_PROJECT_ID=${PROJECT_ID}"
```

**`attribute-condition` が重要。** これがないと、**他人のリポジトリからも認証できてしまう**。

### GitHub Secrets に登録

```bash
gh secret set WIF_PROVIDER --body "projects/.../providers/github"
gh secret set WIF_SERVICE_ACCOUNT --body "github-deployer@....iam.gserviceaccount.com"
gh secret set GCP_PROJECT_ID --body "physique-analytics-xxxx"
```

### Secret Manager に DB 接続文字列を入れる

**Terraform では「箱」だけ作り、値は手動で入れる**（[ADR-0012](adr/0012-terraform.md)）。

```bash
# 箱を作る
gcloud secrets create supabase-pooler-url --replication-policy=automatic

# 値を入れる（履歴に残らないよう注意）
printf '%s' "postgres://...:6543/postgres" | \
  gcloud secrets versions add supabase-pooler-url --data-file=-
```

## 3. CodeRabbit（5分・public無料）

1. [https://coderabbit.ai](https://coderabbit.ai) → **Sign in with GitHub**
2. リポジトリ `physique-analytics` を選んで有効化

設定は任意だが、日本語でレビューさせるなら以下を置く。

```yaml
# .coderabbit.yaml
language: ja-JP
reviews:
  path_filters:
    - "!**/gen/**"      # 生成コードはレビュー不要
    - "!reference/**"   # Phase 0 プロトタイプ
```

## 5. Sentry（後回しでよい・無料）

1. [https://sentry.io](https://sentry.io) → GitHub でサインアップ
2. プロジェクトを作成（**Go / Next.js / Apple** をそれぞれ）
3. 各プロジェクトの **DSN** を取得

DSN の置き場所は [05-インフラ設計.md](05-インフラ設計.md) §10。

**パフォーマンス監視は切る**（`TracesSampleRate: 0`）。無料枠の消費が早いため。

## 6. Cloudflare R2（Phase 3・無料）

1. [https://dash.cloudflare.com](https://dash.cloudflare.com) → R2
2. **Create bucket**: `physique-photos`
3. **Manage R2 API Tokens** → Create API token
  - Permissions: **Object Read & Write**
  - 対象バケットを限定する
4. 取得: Account ID / Access Key ID / Secret Access Key

**公開バケットにしない。** API が署名付きURLを発行する（[ADR-0008](adr/0008-r2-photo-storage.md)）。
