# ADR-0010: 分析UIを作り込まず、MCP 経由での分析を主とする

- Status: Accepted
- Date: 2026-09-12

## Context

要件定義 §4.4（分析・レポート）と §4.5（計画管理）は、当初 Web の主機能として位置づけていた。週次レポートの表示、グラフ、期間比較、月次目標の引き直しなどである。

しかし実際の利用形態を考えると、**分析と計画の見直しは Claude Code に依頼する**ことになる。理由は、知りたいことが事前に定義できないため。

- 「2027年3月と2028年3月で、同じ体脂肪率のときの肩囲を比較して」
- 「睡眠6時間未満だった翌日、ベンチの e1RM は平均でどれくらい落ちてる？」
- 「大会前の減量で、過去2回のうちどちらの方が LBM を守れた？」

**これらに対応する UI は作れない。** 質問は、データが溜まって仮説が立ってから生まれる。固定の画面を用意しても、次に知りたいことは画面の外にある。

一方で分析UIの実装コストは大きい。グラフライブラリの選定、期間フィルタ、指標の切り替え、比較ビュー——いずれも作り込むほど工数が増える。

## Decision

**MCP サーバーを Phase 1 に含め、分析と計画管理は MCP 経由を主とする。Web の分析UIは最小限に留める。**

| 用途 | 主な提供方法 |
|---|---|
| **記録の入力** | **Web / iOS** |
| 今週のサマリ（体重トレンド・PFC残量・今週のアクション） | Web（常設表示） |
| **任意の分析・期間比較・仮説検証** | **MCP（Claude Code）** |
| **週次レポートの全文** | **MCP** |
| **月次目標の引き直し** | **MCP** |
| グラフ・可視化 | Web（Phase 4 以降。必要性が確認できてから） |

要件 §4.4 / §4.5 の項目は削除しない。**提供方法が「Web UI」から「MCP ツール」に変わる。**

## Alternatives considered

**A. 分析UIを Web に作り込む（当初案）**
却下。実装コストが大きい割に、事前に定義できない質問には答えられない。作った画面の多くが使われない可能性が高い。

**B. MCP を Phase 4 のままにする**
却下。Phase 1〜3 の間、分析は手元でリファレンス実装を実行することになり、**CSV エクスポートを挟む手間が残る**。MCP なら API/DB を直接参照でき、記録した内容をその場で分析できる。

また MCP の実装コストは小さい。分析ロジックは API と同じパッケージを共有するため（[ADR-0011](0011-go-analytics.md)）、ツール定義を足すだけで済む。**後回しにする理由がコスト面にない。**

**C. Web の分析UIを完全に作らない**
却下。「今週のアクション」と体重トレンドは毎日見る情報であり、都度 Claude Code を起動するのは過剰。**常設で見たい少数の指標だけ** Web に置く。

## Consequences

**良い影響**

- **Phase 1 のスコープが減る。** グラフ・比較ビューの実装が不要になり、記録が回る状態に早く到達できる
- **事前に定義していない分析ができる。** これは UI では構造的に実現できない
- 計画の引き直し（月次目標の再生成）も MCP から呼べるため、Web に設定画面を作る必要がない
- **MCP と API が同じ分析パッケージを共有できる**（[ADR-0011](0011-go-analytics.md)）。同一バイナリ・同一デプロイに乗るため、運用対象が増えない

**悪い影響 / 受け入れるコスト**

- **分析が Claude Code に依存する。** Claude Code を使えない環境では詳細分析ができない。ただし CSV を書き出してリファレンス実装を直接実行する経路は残るため、完全に不能にはならない
- **第三者に分析機能を見せられない。** ポートフォリオとしては「MCP サーバーの実装」自体を示すことになり、動くUIのスクリーンショットは出せない
- MCP は個人データを扱うため**ローカル実行（stdio）に限定**する。リモート公開はしない
